# ADR-02: Выбор базы данных

## Контекст
Входные данные представляют собой записи о научных публикациях. Каждая запись содержит информацию о 3 типах связанных сущностей: публикации, издания, авторы.  
Ожидаемое количество записей в таблицах - тысячи/десятки тысяч (в зависимости от таблицы) [[BRD-VII-4](../BRD.md#vii-ограничения-и-допущения)].  
Т. к. приложение однопользовательское, конкурентный доступ к базе данных не требуется.  
У разработчика есть опыт работы с реляционными СУБД (в первую очередь, PostgreSQL); опыта с NoSQL базами данных нет.

## Решение
SQLite

### Статус
Принято (29.09.2026)

## Альтернативы
- **NoSQL** - отклонено, т. к. для хранения связанных сущностей больше подходят реляционные СУБД.
- **MySQL**, **PostgreSQL** - отклонены, т. к. требуют более сложной установки и администрирования по сравнению с SQLite.

## Последствия
- 🟢 Отсутствие необходимости отдельной установки базы данных, простота администрирования (создание резервной копии БД сводится к копированию одного файла).
- 🔴 Структура базы данных может оказаться более сложной по сравнению с PostgreSQL из-за отсутствия поддержки сложных типов данных (enum, array); необходимо учитывать отличия SQLite от других реляционных СУБД (type affinity, внешние ключи отключены по умолчанию).
