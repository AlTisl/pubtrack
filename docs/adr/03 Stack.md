# ADR-03: Выбор стека разработки

## Контекст
Десктопное приложение [[ADR-01](01%20Product%20type.md)]. Доступ к сети, а также к периферийным устройствам не требуется. Взаимодействие с файловой системой: импорт/экспорт файлов, обмен данными с БД [[BRD-V](../BRD.md#v-scope)].  
Отображение данных преимущественно в табличном виде.  
У разработчика есть опыт программирования на Python; опыт использования других языков программирования (C#, C++) существенно меньше.

## Решение
Язык программирования - `Python 3`  
Библиотеки `PySide6` (GUI), `csv` (импорт данных), `openpyxl` (экспорт данных в файл `xlsx`), `SQLAlchemy + Alembic` (взаимодействие с базой данных, миграции), `PyInstaller` (сборка exe-файла).

### Статус
Принято (08.10.2026)

## Альтернативы
- **Языки программирования**: `C#`, `C++` - отклонены из-за недостаточного опыта работы с ними.
- **GUI**: `Tkinter` - отклонено, т. к. считается, что виджет `QTableView` в `pySide6` характеризуется лучшей производительностью и функциональностью, чем виджет `TreeView` в `Tkinter`.
- **Импорт/экспорт, преобразования данных**: `pandas` - отклонено, т. к. для примерно 1 тысячи записей в год [[BRD-VI-4](../BRD.md#vi-ограничения-и-допущения)] использование данной библиотеки может быть избыточным.
- **Интеграция с БД**: `sqlite3` - отклонено; связка `SQLAlchemy + Alembic` является более предпочтительной, т. к. позволяет использовать модели таблиц (удобно для взаимодействия с `pySide6`) и автоматизирует миграции БД. `QtSql` - отклонено из-за отсутствия у разработчика опыта использования этого модуля, а также необходимости в этом случае отказа от использования `Alembic`.

## Последствия
- 🟢 Нативное приложение с классическим интерфейсом; у разработчика есть опыт использования этого языка программирования.
- 🔴 Сравнительно большой размер исполняемого файла.
